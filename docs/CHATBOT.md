# Модуль `chatbot` — Telegram-бот для участников клуба

Чисто информационный бот: меню, кнопки, ссылки. **Никаких форм и заявок бот не собирает** —
это не канал приёма заявок на консультацию и не альтернатива форме на Тильде. Если участнику
нужна консультация — бот просто даёт ссылку на форму записи (на лендинге), а дальше это уже
поток `consultations`, не имеющий к боту отношения. Разделение осознанное: это разные формы для
разных целей и разных процессов обработки — не объединяем их ни в модели данных, ни в потоке
уведомлений.

## Технически

- Библиотека — **aiogram** (та же, что и для публикации новостей, см. `docs/TECH_STACK.md`,
  пп.5 и 9).
- Раз бот не собирает многошаговые данные, полноценный `aiogram.fsm` (конечный автомат
  состояний), скорее всего, не понадобится вообще — хватит обработчиков команд и callback-кнопок
  инлайн-клавиатуры. FSM имеет смысл добавить только если появится вложенное многоуровневое
  меню, где важно помнить, на каком шаге навигации находится пользователь — не обязательно для
  плоского меню на кнопках.
- Режим получения сообщений — long polling на старте (не нужен публичный HTTPS-эндпоинт).
- Отдельный процесс/контейнер `bot` в docker-compose (не Celery-таска — см.
  `docs/DEPLOYMENT.md`), потому что боту нужно постоянно слушать входящие сообщения.

## Сценарий (MVP) — плоское меню, без сбора данных

### Главное меню (`/start`)

Кнопки (инлайн-клавиатура):

- **Новости** — ссылка на Telegram-канал новостей клуба.
- **База знаний** — ссылка на раздел базы знаний в ЛК (когда ЛК будет готов; до этого — можно
  временно вести на заглушку/лендинг).
- **Записаться на консультацию** — ссылка на форму на лендинге (Тильда). Бот **не** запрашивает
  имя/контакт/вопрос сам — просто отдаёт ссылку и всё, дальше пользователь работает с формой на
  сайте, это уже вне бота.
- **О клубе** — статический текст (константа в коде бота, отдельная модель в БД ради пары
  абзацев не нужна).

Никакая заявка/запись в БД по итогам этого меню не создаётся — весь функционал бота стоит на
чтение, без записи. Именно поэтому `chatbot` не связан с моделью `ConsultationRequest` — они
по сути даже не соприкасаются напрямую, разве что бот содержит ссылку на форму, которая эту
модель заполняет (но это статическая ссылка, а не программная связь).

## Что осознанно не входит в MVP (и не факт, что вообще понадобится)

- Сбор любых заявок через бота (консультация, запись на тренировку и т.п.) — если такая
  потребность появится, это отдельное архитектурное решение с отдельной моделью под конкретную
  цель, не расширение этого меню задним числом.
- ИИ-диалог / свободный текстовый ввод вопросов — договорились, что бот без ИИ (см.
  `docs/TECH_STACK.md`, п.9).
- Одобрение новостей модератором прямо из бота — см. `docs/ARCHITECTURE.md`, «Возможное
  развитие»: технически отдельная задача, не относится к текущему информационному меню.
