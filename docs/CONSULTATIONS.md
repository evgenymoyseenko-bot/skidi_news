# Модуль `consultations` — заявки на консультацию

Простой лид-трекинг внутри Django admin — без внешней CRM (решение Бро). Источник заявки —
форма на лендинге (Тильда). Это отдельный, самостоятельный поток, никак не связанный с
модулем `chatbot` — бот только даёт ссылку на форму, но не создаёт заявки сам (см.
`docs/CHATBOT.md`).

## Модель

### ConsultationRequest

| Поле | Тип | Комментарий |
|---|---|---|
| name | CharField | Имя обратившегося |
| contact | CharField | Телефон / email / Telegram-юзернейм — то, что оставили в форме |
| message | TextField, blank=True | Вопрос/комментарий, если оставляли |
| source | CharField (choices) | `tilda_form` \| `manual` (заявка, заведённая вручную в admin) |
| status | CharField (choices) | `new` \| `contacted` \| `closed` |
| manager_comment | TextField, blank=True | Заметки менеджера по итогам звонка/переписки |
| handled_by | FK → User, null=True | Кто из менеджеров/админов взял заявку в работу |
| created_at | DateTimeField, auto_now_add=True | |
| updated_at | DateTimeField | |

## Django Admin

- `ConsultationRequestAdmin`: `list_display` — имя, контакт, источник, статус, дата; `list_filter`
  по `status`; сортировка по умолчанию — новые сверху.
- Стандартный воркфлоу: менеджер меняет `status` по мере обработки, оставляет `manager_comment`.
  Отдельных кастомных admin actions не требуется — обычного редактирования полей достаточно
  для этого объёма.

## Приём заявок

### `POST /api/v1/consultations/`

Принимает данные формы с Тильды.

```json
{
  "name": "Иван",
  "contact": "+7 900 000-00-00",
  "message": "Хочу разобраться с карвингом"
}
```

`source` при таком запросе всегда проставляется `tilda_form` на стороне бэкенда — это не
поле, которое передаёт клиент, а факт того, через какой эндпоинт пришла запись.

Аутентификация — статический токен в заголовке (`FORMS_API_TOKEN`, см. `.env.example`) — см.
«Открытый вопрос» ниже насчёт реальных возможностей Тильды передавать заголовки.

## Уведомление менеджеру

При создании `ConsultationRequest` — Celery-таска отправляет уведомление в Telegram (тем же
`aiogram.Bot`-клиентом, что и для публикации новостей, см. `docs/TECH_STACK.md`, п.5) в чат
менеджера/администратора клуба, и опционально — на email. Формат уведомления: имя, контакт,
текст вопроса, ссылка на карточку в admin.

## Открытый вопрос

У Тильды ограниченные возможности настройки исходящего вебхука из конструктора форм (обычно —
POST на URL с полями формы, без гибкой настройки заголовков авторизации из коробки). Перед
реализацией нужно на реальном лендинге skidiscoverer проверить, что конкретно поддерживает
Тильда для веб-хуков форм (заголовки, или только query-параметр с токеном в URL) — не проверял,
это может повлиять на способ аутентификации именно этого эндпоинта.
