исключительно тестовые данные для проверки логики парсера (`parser/tests/fixtures/tass_sample.xml`).

## Почему источники управляются через данные, а не через код

Модель `Source` (см. `DATA_MODEL.md`) хранит источник как запись в БД с полем `parser_config`.
Это значит: добавление, отключение или правка источника — операция в Django admin, не деплой.
Разработчику не нужно закладывать конкретные источники в код вообще — только универсальный
механизм для `source_type = rss` и `source_type = html`. Это явное требование пользователя от
03.09.2026: «модератор должен иметь возможность добавить или убрать источник из парсера».

## Методология подбора источника

Для каждого кандидата перед подключением в продакшен проверить:

1. **Есть ли RSS/Atom-фид.** Из списка ниже реально проверен на RSS только один источник за
   всё время — `rider-skill.ru/feed/` (03.09.2026), но он исключён из списка кандидатов (см.
   выше). То есть **ни один источник из актуального списка ниже RSS не проверен** — это
   обязательный шаг перед подключением каждого.
2. **Разрешён ли парсинг по `robots.txt` и пользовательскому соглашению сайта.** Не проверял
   ни для одного источника ниже — обязательный шаг перед подключением, не формальность.
3. **Частота публикаций vs правило "не старше 30 дней".** Реальная находка 03.09.2026: у
   `rider-skill.ru` последняя запись в RSS была двухмесячной давности — при активном правиле
   `MAX_ARTICLE_AGE_DAYS = 30` (см. `parser/README.md`) такой источник почти всегда даёт
   парсеру пустой результат. Для источников ниже частота публикаций **не проверялась** — это
   важно сделать перед подключением, иначе часть источников будет формально подключена, но
   фактически не будет поставлять новости.
4. **Соответствие критериям редактора.** Промт LLM-редактора (см. `parser/EDITOR_PROMPT.md`)
   сам отфильтрует нерелевантное — но чем более "в тему" источник, тем меньше шума придётся
   отсеивать редактору и тем дешевле по токенам.
5. **Лицензия/атрибуция контента** — при полной перепечатке текста уточнить, не требуется ли
   явная атрибуция/ссылка на первоисточник (в Telegram и в ЛК).
6. **Язык.** Все источники ниже — русскоязычные. Международные источники (см. раздел
   "Пожелание" в конце) потребуют шага перевода — сейчас в пайплайне такого шага нет ни в
   схеме данных (`NewsItem.language` есть, но переводчика нет), ни в промте редактора.

### Пожелание (не обязательно, требует отдельного архитектурного решения)

Пользователь предложил (04.09.2026) добавить по одному тематическому горнолыжному порталу
Америки, Европы, Японии, Австралии/Новой Зеландии — явно как необязательное пожелание, не
задача. Не искал источники под это и не добавлял их сейчас. Важная оговорка от самого
пользователя: такие источники будут не на русском — потребуется шаг перевода, которого сейчас
нет в пайплайне ни на уровне схемы (`NewsItem` не содержит поля "исходный/целевой язык"), ни в
промте редактора (промт написан и оценивает критерии по-русски). Если решим делать — это
отдельный небольшой архитектурный вопрос (где переводить: до редактора отдельным шагом, или
доверить сам перевод редактору как часть его промта), не просто "добавить источники в список".
