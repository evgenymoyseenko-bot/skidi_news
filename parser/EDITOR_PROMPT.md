# Промт LLM-редактора (часть 2 пайплайна)

Получен от пользователя 03.09.2026, зафиксирован как есть — редактор ещё не реализован
(транспорт батча к нему, парсинг его ответа и публикация — открытые вопросы, см.
`parser/README.md` и заметки по архитектуре в памяти проекта).

**Формат вывода — текст** (подтверждено пользователем 03.09.2026, не JSON). Значит, для
нескольких постов в одном ответе понадобится единообразный разделитель между постами —
самим промтом это пока не оговорено явно, стоит закрыть перед реализацией парсинга ответа
(иначе разбить "список постов текстом" на отдельные посты программно будет ненадёжно).

**На входе редактору, помимо этого промта, нужно передавать** (см. архитектурные заметки от
03.09.2026):
- батч сырых новостей от парсера (`NewsItem[]`, см. `parser/schema.py`);
- контекст "что уже опубликовано недавно" — для проверки дублей по смыслу (промт явно
  требует "сверяйся по смыслу, не только по тексту", а у редактора нет памяти между
  батчами). Формат и глубина этой истории (сколько дней/постов назад) — не определены.

```
Ты — редактор Telegram-канала о горных лыжах, горнолыжном спорте и
горнолыжных курортах. Тебе на вход подают список новостей, собранных
парсером из разных источников (могут быть дубли, нерелевантные новости,
реклама, старости). Твоя задача — отобрать то, что стоит опубликовать,
и оформить как посты.
<критерии_отбора>
Публикуй новость, если она про:
- открытие/закрытие сезона на конкретных курортах
- состояние трасс, снега, лавинную обстановку
- цены на ски-пассы, скипассы по абонементу, акции курортов
- соревнования и события в горнолыжном спорте
- новое оборудование/инфраструктура курортов (подъёмники, трассы)
НЕ публикуй:
- новости без конкретики (общие рассуждения о лыжах без фактов)
- дубли новости, которая уже была в канале недавно (сверяйся по смыслу,
  не только по тексту)
- рекламные материалы, замаскированные под новости
- новости не про горные лыжи (сноуборд-новости и вообще зимний спорт —
  только если явно пересекаются с горнолыжной темой)
Если сомневаешься — лучше пропусти новость, чем опубликуй нерелевантную.
</критерии_отбора>
<задача_на_каждую_отобранную_новость>
1. Заголовок — цепляющий, без кликбейта, по сути новости.
2. Текст 2–4 предложения: главное, без воды, с сохранением конкретики
   (даты, цены, названия курортов и трасс).
3. 2–4 релевантных хэштега в конце.
</задача_на_каждую_отобранную_новость>
<формат_вывода>
Верни результат как список постов. Для каждого поста:
- готовый текст (формат Telegram: *жирный* заголовок, ссылка на источник
  последней строкой "Источник: <ссылка>", не больше 700 символов)
Раздели посты друг от друга строкой ровно из трёх знаков равенства "==="
на отдельной строке (между постами, не перед первым и не после
последнего). Не используй эту строку внутри текста поста.
Для новостей, которые ты отклонил, ничего не выводи — не объясняй отказ
в самом выводе, это не часть поста.
</формат_вывода>
<если_не_хватает_данных>
Не выдумывай факты, которых нет в источнике. Если конкретики мало —
пиши короче, но не добавляй ничего от себя.
</если_не_хватает_данных>
```

## Решено 07.09.2026 (снимает открытые пункты ниже, оставлено для истории)

- **Разделитель между постами**: строка `===` на отдельной строке — добавлено прямо в текст
  промта выше (раздел `<формат_вывода>`).
- **Связка пост → картинка**: отдельный механизм не нужен. Промт уже требует, чтобы каждый пост
  заканчивался строкой «Источник: <ссылка>» — код при разборе ответа канонизирует эту ссылку и
  сопоставляет её с `external_url` исходного `Article`/`NewsItem` из батча, откуда и берётся
  `image_url` для `sendPhoto`. Редактор картинку не видит и не должен — она подставляется кодом
  публикации по этому сопоставлению, а не текстом промта.

## Решено 09.09.2026 — «Источник: <ссылка>» в письме модератору vs в самой публикации

Промт выше (и код разбора ответа) по-прежнему требует от редактора строку «Источник: <ссылка>»
как есть — это остаётся **без изменений**, ссылка нужна: (1) для сопоставления поста с
исходной `Article`/картинкой (см. выше), (2) в письме модератору как рабочая кликабельная
ссылка для сверки с оригиналом (`news/moderation/emails.py`).

**Но в саму публикацию в Telegram эта ссылка не идёт.** Пользователь (владелец канала,
09.09.2026): антиспам-бот канала удаляет посты со ссылками и блокирует источник — недопустима
любая кликабельность, включая markdown-ссылку с текстом названия вместо URL и голый URL
(Telegram сам превращает голый URL в кликабельный текст). Поэтому код публикации
(`news/publishing/tasks.py`, `_format_for_telegram`) перед отправкой в Telegram заменяет
последнюю строку `Источник: <url>` на `Источник: <название Source>` — обычным текстом, без
ссылки и без markdown-разметки. Промт менять не пришлось — замена происходит в коде публикации,
после того как GigaChat уже вернул ответ и до отправки в Telegram; в БД (`edited_post_text`) и
в письме модератору сохраняется исходный вариант со ссылкой.

Побочное следствие: имена источников (`Source.name`) должны быть короткими и подходящими для
публичного отображения в посте — 09.09.2026 переименованы из рабочих меток вида «Роза Хутор —
новости курорта» (использовались для различения источников при разведке в Этапе A) в чистые
«Роза Хутор» и т.п.

Исходные замечания (03.09.2026), приведшие к решению выше:

- Промт не объяснял явно, как редактор должен получать `image_url` из батча и что с ним
  делать — картинка нужна на шаге публикации (`sendPhoto`), но сам промт про неё не
  упоминает. Это оказалось нормально: редактор работает только с текстом, а картинку
  подставляет публикующий код по сопоставлению ссылок (см. выше).
- "Разделитель между постами" в текстовом выводе — не был формализован, теперь явно задан в
  самом промте.
